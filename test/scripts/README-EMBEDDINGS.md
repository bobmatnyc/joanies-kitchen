# Embedding Generation Script

Production-ready script for generating semantic embeddings for all recipes.

## Embedding model (#96, D57)

All embeddings use **`BAAI/bge-small-en-v1.5`**, 384 dimensions, CLS pooling,
L2-normalised. The app and the Python script produce the same vectors:

| Writer | How |
|---|---|
| App runtime and the TS scripts (`src/lib/ai/embeddings.ts`) | `@huggingface/transformers`, ONNX export `Xenova/bge-small-en-v1.5`, fp32 (`onnx/model.onnx`), in-process, no network |
| `generate_embeddings_local.py` (wrote ~93% of stored rows) | sentence-transformers `BAAI/bge-small-en-v1.5`, `normalize_embeddings=True` |

- **Passages** (recipes, `generateEmbedding`, `generateRecipeEmbedding`,
  `generateEmbeddingsBatch`) take **no prefix**.
- **Search queries** go through `generateQueryEmbedding`, which prepends
  `Represent this sentence for searching relevant passages: `.
- Rows are labelled `BAAI/bge-small-en-v1.5` in `recipe_embeddings.model_name`
  and `recipes.embedding_model`.
- Cost is $0. There is no API key, no cost-ledger entry and no daily-cap check.
  There is no Jina fallback; a load or inference failure throws `EmbeddingError`.

### Model files

The 133 MB fp32 weights are **not committed**. `prebuild` runs
`scripts/fetch-embedding-model.ts`, which downloads the files listed in
`src/lib/ai/embedding-model.ts` from Hugging Face at a pinned commit, checks
each file's sha256, and writes them to `models/` (git-ignored). A mismatch
fails the build. A file already present with the right hash is reused.
`next.config.ts` bundles `models/**` and the linux-x64 ONNX runtime into the
server functions (`outputFileTracingIncludes`). The function never downloads.

Why not commit them: 133 MB in git history grows every clone permanently, and
Git LFS would need Vercel's LFS setting plus LFS bandwidth quota. The pinned
download with a sha256 check gives the same reproducibility.

Fetch locally before running tests or scripts that embed:

```bash
pnpm exec tsx scripts/fetch-embedding-model.ts
```

### Parity checks

- `src/lib/ai/__tests__/embeddings-parity.test.ts` compares the TS embedder
  with vectors from the Python model
  (`src/lib/ai/__tests__/fixtures/bge-small-reference.json`, generated by
  `fixtures/make_bge_reference.py`); it requires cosine >= 0.99 and skips when
  `models/` is absent.
- `scripts/verify-bge-parity.ts <database-url> [--limit=20]` re-embeds N
  stored rows whose `model_name` is `BAAI/bge-small-en-v1.5` and checks cosine
  >= 0.99, norm ~1 and length 384 for each. It is read-only (one SELECT).

## Quick Start

```bash
# Test on 10 recipes (dry-run)
pnpm embeddings:generate:test

# Generate embeddings for all recipes
pnpm embeddings:generate

# Resume from checkpoint if interrupted
pnpm embeddings:generate:resume
```

## Features

- ✅ **Checkpoint/Resume**: Saves progress every 50 recipes
- ✅ **Retry Logic**: 3 automatic retries with exponential backoff
- ✅ **Error Logging**: Detailed logs in `tmp/embedding-errors.log`
- ✅ **Progress Tracking**: Real-time ETA and processing rate
- ✅ **Quality Validation**: Validates embedding dimensions and values
- ✅ **Dry-Run Mode**: Test without generating embeddings
- ✅ **Limit Mode**: Test on small batches

## Commands

```bash
# NPM Scripts
pnpm embeddings:generate:dry-run    # Dry run (default)
pnpm embeddings:generate:test       # Test on 10 recipes
pnpm embeddings:generate            # Execute full generation
pnpm embeddings:generate:resume     # Resume from checkpoint

# Manual Commands
npx tsx scripts/generate-all-embeddings.ts                    # Dry run
npx tsx scripts/generate-all-embeddings.ts --execute          # Execute
npx tsx scripts/generate-all-embeddings.ts --limit=10         # Test
npx tsx scripts/generate-all-embeddings.ts --execute --resume # Resume
npx tsx scripts/generate-all-embeddings.ts --batch-size=10    # Custom batch
npx tsx scripts/generate-all-embeddings.ts --delay=2000       # Custom delay
```

## Configuration

- **Model**: BAAI/bge-small-en-v1.5 (384 dimensions), in-process
- **Batch Size**: 10 recipes per batch
- **Delay**: 2000ms between batches (pacing for the DB only; the embedder has no rate limit)
- **Max Retries**: 3 attempts per recipe
- **Checkpoint Interval**: Every 50 recipes

## Estimates (for 3,276 recipes)

- **Time**: ~2.5-3 hours
- **Cost**: $0 (local inference)
- **Rate**: ~15-20 recipes/min

## Output Files

All files saved to `tmp/` directory:

1. `embedding-generation-checkpoint.json` - Progress checkpoint
2. `embedding-errors.log` - Error details
3. `embedding-generation-report-*.json` - Final report

## Troubleshooting

### Model Files Missing

`EmbeddingError` with code `CONFIG_ERROR` means `models/Xenova/bge-small-en-v1.5`
is absent. Run `pnpm exec tsx scripts/fetch-embedding-model.ts`. No API key is needed.

### Resume from Interruption

```bash
pnpm embeddings:generate:resume
```

### Check Progress

```bash
# View checkpoint
cat tmp/embedding-generation-checkpoint.json

# View errors
cat tmp/embedding-errors.log

# Check database coverage
pnpm test:embeddings
```
